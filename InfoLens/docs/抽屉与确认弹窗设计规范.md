# 鑫向晨 CRM 抽屉与确认弹窗设计规范

版本1.0，生效日期2026-11-06。依据用户确认的商品右抽屉及全站新增/详情改造要求。

## 1. 组件与使用范围

- 新增、编辑、详情、导入预览、记录、报错详情和业务钻取统一使用右侧抽屉。
- 表单及普通详情统一使用 `components/ui/FormDrawer.jsx`；有详情/编辑多状态、自定义底栏的复合流程使用 `AppDrawer.jsx`。
- 所有布局最终由AppDrawer封装Arco Drawer。禁止业务直接使用Drawer、FormModal或Modal.info承载业务内容，禁止另写蒙层及固定面板。
- 删除、结束政策、移除标签等短二次确认保留Modal.confirm；照片删除标签现有声明式确认Modal保留。
- 图片预览保留图片预览组件；下载沿用原流程，不强行转换为抽屉。

## 2. 布局

- 默认从右侧展开。small=520px，medium=720px，large=920px；统一不超过100vw。
- 标题及底部操作区固定，内容区是主要滚动区；表格数据区仍遵守表格设计规范，避免重复滚动wrapper。
- 底部按钮区始终贴合抽屉底边，使用不透明背景并位于正文之上；内容超高时只在正文内部滚动，不能随内容把按钮挤出视口。共用样式必须覆盖Arco焦点锁定包装层的高度传递，保留键盘焦点锁定。
- 小屏内容换行，不能因旧弹窗CSS定宽或高度限制裁切正文。
- 所有新增/编辑抽屉的独立字段必须单列排列，禁止终端编码与客户名称、角色与状态、价格与件数等并排。
- 字段容器使用drawer-field-stack，统一由FormDrawer约束为单列；业务CSS和媒体查询不得改回双列。
- 表单标签、字段顺序与对应详情保持业务一致；复杂政策表单按业务分组保留必要结构。
- 同一个逻辑字段的组合控件（例如规格的数量/单位、命中条件的字段/运算符/值）可同行；统计卡片和结果表格不属于并行编辑字段。
- 长名称、地址、备注完整换行；列表截断不应带入详情。
- 默认禁止点遮罩误关闭，支持关闭按钮与Esc；保存/导入期间禁止关闭。
- Select/Tooltip/Popover等弹层挂document.body，避免被内容区裁切。

## 3. 行为

- 新增保留必填项和默认值；编辑保留版本号、空值语义及原有后端权限。
- 详情为只读，存在编辑权限时提供编辑入口；用户管理等原编辑入口不扩展角色权限。
- 商品的详情/编辑/新增共用同一状态抽屉，取消编辑回原详情，成功保存后以接口返回数据展示详情。
- 其他模块保留原保存成功关闭/刷新行为。关闭、返回上级和取消的结果必须明确，不能悄悄提交。
- 保存/导入确认期间所有提交入口禁用并显示loading；关闭按钮、Esc、底部取消统一禁用。失败保留输入及错误提示。照片后台任务已提交后允许沿用原有关闭与恢复机制，不锁定整个页面等待长任务。
- `FormDrawer`支持onSubmit；迁移旧导入流程兼容onOk，预览→确认、禁用条件、确认按钮状态必须保留。
- footer=null表示内容内自带操作或无需底栏，不能擅自添加确认提交。
- 嵌套钻取逐层关闭，复制/导出/筛选/分页能力不得丢失。

## 4. 工程与验收

- 不修改API、业务统计、权限和数据结构来适配展示容器。
- 删除被替代的Modal.info、FormModal以及无效Modal尺寸/高度/标题样式。
- 开发入口为frontend/AGENTS.md与前端开发原则；运行npm run check及npm run build。
- check:drawers验证右侧/视口尺寸、保存锁定、按钮禁用、导入兼容、只读关闭和全站入口约束。
- 浏览器验收至少覆盖新增空表单、详情→编辑、失败保留、关闭、窄屏、长字段和含表格钻取。真实写入测试使用独立测试数据。
- 未执行的保存/导入或权限分支必须写入验收记录，不能以构建通过代替交互验证。

## 5. 示例

```jsx
<FormDrawer title={record ? '编辑客户' : '新增客户'} visible={visible}
  size="medium" loading={saving} okDisabled={!valid}
  onSubmit={save} onCancel={close}>
  <CustomerFields />
</FormDrawer>
```

复杂详情面板使用AppDrawer传入明确的footer，状态留在业务feature；共用组件不包含客户/政策等字段。
