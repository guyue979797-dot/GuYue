# 鑫向晨 CRM 开发与设计规范

版本3.0 · 2026-11-08 · 用户确认的终端明细样板为视觉基准。

本规范适用于全站和后续功能。专项细节见[表格](表格设计规范.md)、[抽屉](抽屉与确认弹窗设计规范.md)、[焦点](输入控件焦点设计规范.md)。最新业务需求优先；不得删改既有权限、统计口径、导入确认、导出、钻取或任务恢复来满足视觉规则。

## 1. 判断标准

每个决定同时降低三种成本：用户理解和操作成本、开发维护成本、智能体识别及回归成本。优先删除重复信息与重复实现，使用标准组件和明确的语义。页面需要长段说明才看得懂时先改布局；仅保留会影响决策的口径、危险操作提醒、错误与恢复提示。

## 2. 页面结构

- 应用顶栏只承载当前位置、通知、头像。业务新增、上传、导出放在内容区工具栏，不占用顶栏。
- 列表页顺序：筛选卡片 → 列表卡片（标题/总数/操作 → 状态 → 表格 → 分页）。照片保留图片分组，价格与用量保留政策卡片。
- 左右外边距8px，上下12px；无最大内容宽度或宽屏居中留白。只保留必要的卡片层级。
- 筛选/列表卡片：白底、灰色1px边框、8px圆角、最轻阴影。筛选内边距12px，表格内边距8px，卡片间距12px。
- 列表工具栏最小48px。窄屏操作换行，不遮挡标题、通知、头像或表格；筛选自身负责换行，业务页不复制响应式规则。
- 表格数据区只保留一个纵向滚动容器，分页始终可达；照片区、政策卡片区保留各自明确的内容滚动区。

## 3. 排版与颜色

全部采用tokens.css。当前位置/页面标题14px、500字重；列表标题14px、600；正文14px、表格13px、辅助信息12px。侧栏品牌16px。仅真正需要强调的业务金额可用24px，不用大字号做标语。

沿用样板的浅灰页面、白色卡片、品牌选中态和Arco主按钮。颜色表达状态或交互；人员、日期、普通统计不做彩色胶囊。成功/失败等状态同时提供文字。Arco的--primary-*是RGB通道，禁止重定义及直接作为完整颜色。

## 4. 筛选

- 使用FilterBar声明fields/values/onChange/onSearch/onReset，标签默认可见。选值后仍能识别字段含义。
- 标签可见时，占位文字不重复字段名称：下拉空值用“全部”，月份用“选择月份”，文本框只提示输入方式（如“输入编码”“支持模糊搜索”）；隐藏标签时仍保留字段识别信息。必要的特殊选择提示可保留。
- 公共筛选区默认提供收起/展开，初始展开；收起仅隐藏控件，不清空条件、不自动查询或重置，表格自动利用释放空间。入口使用文字按钮及aria-expanded。
- 条件按逻辑分行，动作放末行右侧；小窗口自动换为两列/单列。多选使用原生responsive折叠与+N，不撑高整栏。
- 草稿与应用查询分离，查询/重置/每页条数变化回第一页；旧请求不得覆盖新请求。
- 保留已确认的特殊行为，如政策即时筛选、字段内OR与字段间AND。不能为了统一视觉悄悄改变查询口径。
- 不重复展示已选条件标签或操作说明，除非用户确实需要额外的检索结果/缺失项信息。

## 5. 表格与操作

- 只用DataTable，截断用TableText，行操作用TableRowActions；复杂单元格提供widthText。
- 按可见内容测量基准列宽；不足容器时按比例撑满，超出时内部横向滚动。保留拖动、双击/Home恢复与键盘调整。
- 表头、正文共用一份列宽；不得用复制DOM、覆盖冻结层或布局补丁解决对齐。
- 详情/编辑主入口为中性文字，无常驻底色和边框，悬停下划线，保留focus-visible。次要操作进更多菜单，菜单为空不显示。
- 点击数字、标签和编码使用button，图标操作有aria-label；不把整行点击作为唯一入口。
- 编码保留文本语义，格式、空值、单位、零值统一；不得修改业务值。排序、选择、分页、导出和钻取不得丢失。

## 6. 抽屉与表单

- 新增/编辑/详情使用FormDrawer或AppDrawer，短二次确认使用Modal.confirm。
- 单列字段；同一个逻辑字段的组合控件可同行。标题和底部操作固定，正文滚动，宽度不超过视口。
- 点击遮罩、关闭按钮、Esc和取消均使用同一关闭保护：只读/未修改可关闭；有未保存修改先确认；保存/导入中禁止关闭和重复提交。
- 上传预览未提交视为待处理内容，关闭先确认；后台任务已提交可按原任务恢复设计关闭。
- 新表单通过useDraftState保存草稿及重置基线，dirty以真实值差异判断；不读React内部状态、不靠DOM事件推测变更。
- 失败保留输入、显示可行动错误；校验可定位字段；关闭后恢复触发点焦点。密码不回显，角色及版本保护沿用后端。

## 7. 实现边界

- Arco负责基础控件；components/ui负责统一交互；features负责业务；api负责请求；styles负责对应作用域。
- 不新增UI库，不在App.jsx/legacy.css堆业务，不在各页面复制列宽、焦点、关闭确认或筛选布局。
- 先扩展已有组件再新增；只被一个feature使用的逻辑留在feature。不要为视觉统一新增不必要的状态与抽象。
- CSS精准定位，删除被替代规则；禁止全局table/td/th补丁、nth-child字段定位、未说明!important。
- 使用label/aria-label、稳定rowKey和真实disabled/loading状态，便于键盘和自动回归；不依赖坐标识别唯一业务操作。

## 8. 开发与复测门槛

开发前阅读本规范和相关专项，记录业务保持清单、接口、角色、状态、复用组件及回滚范围。实现后执行npm run check、npm run build、git diff --check；check:ui作为设计契约随check执行。

浏览器按[复测清单](页面复测清单.md)执行：1280/1440/1920及窄屏；正常、加载、空、错误、长文本、多选；筛选、分页、列宽、详情/编辑、保存失败、遮罩关闭；通知/头像、嵌套抽屉、权限、导入预览及导出。只对独立测试数据写入，不用正式记录试删除或导入。

记录必须区分自动检查、实际浏览器验证及未覆盖项；构建通过不等于业务通过。每个受影响feature至少一份同尺寸截图和关键交互结果。无关业务、部署及数据库迁移不混入UI变更。
