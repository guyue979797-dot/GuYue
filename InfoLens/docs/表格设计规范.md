# 鑫向晨 CRM 表格设计规范

版本：1.1；更新日期：2026-11-08。适用于所有页面、弹窗、导入预览与钻取结果表格。
依据：用户确认的商品表格交互，本文件的列宽规则取代此前“业务页面手写固定width”的要求。

## 1. 唯一组件入口

- 新表格必须使用 `frontend/src/components/ui/DataTable.jsx`，使用列配置和数据记录。
- 禁止直接使用Arco Table或新增原生table，禁止复制列宽/拖动代码。
- 历史弹窗使用AdaptiveTable适配已有行内容，最终仍由DataTable渲染；仅用于兼容现有表格，新功能不要继续新增行标记适配。
- 列宽统一由useTableColumnWidths及tableColumnSizing负责，业务组件只描述字段、显示内容与合理边界。

## 2. 宽度规则

1. 自动宽度按当前展示数据的可见文本计算，包含表头、格式化金额/日期、标签和内边距；隐藏Tooltip和菜单内容不参与计算。可排序列表头额外预留排序图标空间，标题与排序图标保持同行。
2. 默认自动最小宽度80px、最大宽度360px；业务可用minWidth/maxAutoWidth覆盖。
3. 商品全称自动上限420px，商品260px，编码260～320px。多行证据按最长行测量。
4. 复杂业务组件必须提供widthText(record)，复杂表头可提供widthLabel；不得仅依据原始数值估计格式化控件宽度。
5. 达到自动上限时限制溢出，长文本使用TableText，实际截断后悬停查看完整内容；不要再在单元格内叠加独立固定像素上限。
6. 手动调节优先于自动计算，分页、筛选、刷新数据不覆盖本次挂载内的手动宽度。补足空白优先分配给未手动调整的列；所有列均已手动调整时，仍以存储宽度为基准按比例补足。离开页面或刷新后恢复自动宽度。
7. 按2026-11-08用户最新要求，总列宽不足容器时按内容宽度比例分配剩余空间，使所有字段共同撑满可用宽度；maxAutoWidth仅限制内容测量基准，不限制补足空白后的展示宽度。超过容器时保持原列宽并在表格内横向滚动，不压缩到内容最小宽度以下。

## 3. 调节交互

- 每个数据列的表头右侧提供9px命中区及分隔线，悬停显示col-resize。
- 拖动以实际渲染列宽起算；手动默认范围64～1200px，可超过自动上限。
- 复杂列的minWidth也是手动最小值；例如政策进度列不小于400px，以保留原业务点击能力。
- 双击恢复该列自动宽度；聚焦分隔线后左右方向键每次调整16px，Home恢复自动宽度。
- Pointer Capture处理拖出表头、释放和取消；不得保留全局鼠标事件或影响业务排序按钮。
- 复选框等Arco辅助列保持组件原生行为，横向宽度计算须计入辅助列。

## 4. 布局与业务保护

- 表头与表体必须使用同一份列宽，禁止复制冻结层、分别测宽或分别维护横向基准。
- 一张表保留一个数据区纵向滚动容器；弹窗表格随视口收缩，不能越出弹窗边界。
- 有分页的固定容器表格通过DataTable的fitContainer按正文实际位置测量可用高度，扣除表头并留出分页区域；不能把整个表格高度直接当作正文scroll.y。自然高度的钻取表格保留原最大高度，禁止强行将Arco内部多层容器全部设为100%造成末行和横向滚动条裁切。
- 排序、选择、分页、详情、导出、复制、告警钻取、加载和禁用状态不得因宽度改造丢失。
- 弹层挂载document.body；样式限定于.data-table及所属业务作用域。
- 不做后端字段、业务统计和权限语义变更。

## 5. 新表格示例

```jsx
<DataTable data={records} columns={[
  { key: 'name', title: '名称', maxAutoWidth: 320,
    render: (_, row) => <TableText value={row.name} /> },
  { key: 'amount', title: '金额',
    widthText: row => `¥${Number(row.amount).toFixed(2)}`,
    render: (_, row) => `¥${Number(row.amount).toFixed(2)}` },
]} />
```

## 6. 强制验收

- 执行 `npm run check` 和 `npm run build`（frontend目录）。
- check:tables检查内容测量、边界、拖动/恢复、弹窗条件列与回调，以及禁止绕过DataTable的入口规则。
- 浏览器验证空数据、短文本、长文本、多标签、多行证据、分页/筛选后的宽度、窄视口及横向滚动。
- 检查表头/表体对齐；拖动不得触发排序、选择或按钮操作。
- 涉及复杂单元格时补充widthText及最小宽度，并验证原业务点击仍可使用。
- 不得仅以构建通过代替交互验收；实际未验证的浏览器或手势必须在记录中说明。
