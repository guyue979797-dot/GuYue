# 输入控件焦点设计规范

版本1.0，2026-11-07。适用于销售、商品、客户、照片、权限、业务钻取及独立登录页。

## 1. 单一外框归属

每个逻辑输入控件只能有一个负责焦点外框的元素。不能给外框和内部输入元素同时增加边框、outline或焦点阴影。全站通用规则集中在`frontend/src/styles/focus.css`，在业务样式之后加载；禁止业务页面另写输入焦点外框补丁。

| 控件 | 焦点外框归属 | 内部编辑元素 |
| --- | --- | --- |
| 普通Arco Input、TextArea | 控件自身 | 不额外叠加outline |
| 金额前缀、单位后缀、搜索、密码组合、InputNumber | Arco实际外框 | 不绘制第二层outline |
| Select、多选搜索、InputTag、日期/月/范围 | Arco外层状态框 | 内部输入只负责文字、光标和选区 |
| 商品多编码等单值组合控件 | 标记data-focus-owner的容器 | 内嵌Input无边框、无阴影、背景透明 |
| 客户备注、只读复制框等原生文本控件 | 标记data-focus-owner的控件自身 | 单一边框高亮 |
| 原生按钮和链接 | 自身的focus-visible轮廓 | 不取消键盘焦点 |

相邻但独立的筛选条件仍各自拥有焦点外框，外部中性分组线不能额外绘制焦点框。商品规格的数量/单位等独立控件不要因为处于同一行就统一标记为同一个data-focus-owner。

组合控件中的删除标签等按钮是独立交互项，保留其键盘焦点提示；不要为了消除输入框双重边框而隐藏按钮焦点。

## 2. 状态与可访问性

- 默认焦点只高亮所属边框，不加第二层外扩阴影。Arco的error、warning、disabled状态由组件本身处理，不用统一蓝色规则覆盖。
- 自定义原生或组合控件使用`data-focus-owner`；错误/警告状态使用`data-focus-status="error"`或`"warning"`，这些状态在聚焦时仍优先显示。
- 禁用控件不可聚焦，不伪造焦点；只读复制字段允许聚焦和选择文本，不能与禁用混淆。
- 不得使用全局`input { outline:none }`或`*:focus { outline:none }`清除所有键盘提示。仅在已经有明确外框负责焦点的内部编辑器上移除重复outline。
- 隐藏的文件input不承担可视焦点外框，由触发上传的可聚焦按钮提供提示；离屏剪贴板临时textarea不属于业务输入框。
- 独立登录页不加载应用业务CSS，由登录表单自身的输入边框提供同样的单层高亮；不再叠加外扩焦点阴影。

## 3. 工程约束

```jsx
<div className="product-multi-input" data-focus-owner>
  <ProductCodeTags />
  <Input aria-label="商品编码" />
</div>

<textarea data-focus-owner className="customer-textarea" />
```

- `focus.css`是应用输入焦点样式唯一入口；业务CSS可设置尺寸、间距、普通背景和布局，不重复设置输入框焦点outline、border、box-shadow。
- 以当前Arco实际DOM为准。现有版本前后缀框为`.arco-input-inner-wrapper`，禁止继续使用失效的`.arco-input-wrapper`。
- 组件库升级或新增输入种类时，检查内部input与实际外框；在集中规则中补充覆盖，并复测以下矩阵。
- 不将客户、商品等业务字段写入通用焦点样式；不要用字段序号、nth-child或重复的局部覆盖解决问题。

## 4. 必须验收

执行`npm run check:focus`（已纳入`npm run check`）和`npm run build`。检查会拒绝过期选择器、页面局部焦点外框、新增原生文本控件未声明归属，以及登录页重复阴影。

浏览器至少覆盖：普通文本、金额前缀、数量后缀、搜索、密码、可搜索单选、多选搜索、独立标签、日期/月/范围、多行计数、原生备注、只读复制、自定义多编码、错误/警告/禁用、键盘Tab及按钮焦点。

必须验证外框仅一层、内部无outline或第二层边框、前后缀不被轮廓穿过、只读仍可复制、错误色在聚焦后保留、禁用不被激活、窄屏不横向溢出。未能执行的浏览器分支必须在验收记录说明，不能用静态检查冒充实际聚焦测试。
